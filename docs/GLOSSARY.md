# Glossary

The vocabulary used in code, tests and documents. One name per concept; no synonyms in code.

| Term                   | Meaning                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Recording              | One capture as the camera stored it: one `.insv` file, or the `_00_`/`_10_` pair of older cameras, plus the trailer metadata.                                                                                                                                                                                                                               |
| Trailer                | Insta360's metadata block after the MP4 boxes, ending in the 72-byte footer with the magic string. Wrapped in an `inst` box on newer firmware, bare on older firmware.                                                                                                                                                                                      |
| Record                 | One typed payload inside the trailer (info, gyro, exposure, thumbnail, ...), addressed by its record id.                                                                                                                                                                                                                                                    |
| Record locator         | How record payloads are found, chosen from the header before the footer: through the index record, or by walking headers backwards (`locateRecords`).                                                                                                                                                                                                       |
| Info record            | Record id 1: the protobuf message with camera identity, calibration strings and timing fields. Parsed into a `RecordingInfo`.                                                                                                                                                                                                                               |
| Calibration string     | The `offset`, `offset_v2`, `offset_v3` or `offset_v6` text describing each lens. Parsed into a `CalibrationSet`.                                                                                                                                                                                                                                            |
| Calibration source     | Where the info record keeps one calibration string, and the name the camera's schema gives it: declared once (`CALIBRATION_SOURCES`), read by the parser and named by the selection.                                                                                                                                                                        |
| Calibration preference | The order the calibration strings are tried in; the first usable one draws the lenses (`CALIBRATION_PREFERENCE`, legacy first, ADR 0023).                                                                                                                                                                                                                   |
| Calibration set        | All lenses of a recording on a shared calibration canvas, with the version of the string it came from.                                                                                                                                                                                                                                                      |
| Lens calibration       | One lens: its lens model, orientation (yaw, pitch, roll) and translation relative to lens 0.                                                                                                                                                                                                                                                                |
| Lens model             | Strategy mapping a direction in the lens frame to a pixel on the calibration canvas: MEI, polynomial or equidistant.                                                                                                                                                                                                                                        |
| Mei distortion         | The distortion terms of a Mei lens as families by increasing order: radial terms of r², Brown's tangential pairs, thin-prism shifts (`MeiDistortion`). Every Mei string version fills some of them.                                                                                                                                                         |
| V6 term reading        | Which of the v6 string's thirteen distortion tokens a lens is drawn with, and in which role (`V6TermReading`, ADR 0032).                                                                                                                                                                                                                                    |
| Radial scale           | The factor on the image radius a lens is drawn at, against its model's reading of the string: 1, or what a reading measured it needs (ADR 0023). Applied when the stitching setup is built.                                                                                                                                                                 |
| Calibration canvas     | The pixel space the calibration is expressed in: lens images side by side (10752 x 5376 on the X5). Track pixels are a scaled window of it.                                                                                                                                                                                                                 |
| Lens frame             | Right-handed frame with x to the right, y down, z along the optical axis of one lens.                                                                                                                                                                                                                                                                       |
| Field edge             | The half field of view beyond which a lens sees nothing; 100 degrees on X-series lenses. The legacy calibration's radius marks 96 degrees, not the edge (ADR 0023).                                                                                                                                                                                         |
| Gyro track             | All IMU samples of a recording: capture timestamp, acceleration (g), angular velocity (rad/s).                                                                                                                                                                                                                                                              |
| Gyro sample layout     | Strategy for one sample's bytes: raw (20 bytes, offset-binary) or float (56 bytes).                                                                                                                                                                                                                                                                         |
| Exposure record        | Record id 4: per captured frame, capture timestamp and shutter time.                                                                                                                                                                                                                                                                                        |
| Capture clock          | The camera's monotonic microsecond clock shared by gyro samples, exposure entries and `first_frame_timestamp`.                                                                                                                                                                                                                                              |
| Capture time           | The capture-clock timestamp of one frame's exposure start.                                                                                                                                                                                                                                                                                                  |
| Frame times            | Capture time, exposure and readout per encoded frame, aligned to the video track.                                                                                                                                                                                                                                                                           |
| Lens layout            | How lens images are stored: multi-track (one file, one track per lens), split files (`_00_` and `_10_`), or packed (both circles in one frame).                                                                                                                                                                                                             |
| Lens source            | Where one lens's pixels come from: an input, a track and a rectangle within the frame.                                                                                                                                                                                                                                                                      |
| Random access source   | Port for reading byte ranges from a file or URL.                                                                                                                                                                                                                                                                                                            |
| Inspection             | What a recording's file holds, condensed to plain data without playing it: boxes, trailer records, info record, calibration, and gyro and exposure summaries (`RecordingInspection`).                                                                                                                                                                       |
| Byte range             | An offset and a length in a source; end exclusive.                                                                                                                                                                                                                                                                                                          |
| Sample table           | Where every sample of every track lies in a file, when it plays, for how long and whether decoding may start there: the movie box as the core reads it (`SampleTable`, a `TrackSampleTable` a track).                                                                                                                                                       |
| Codec reader           | Port: the decoder configuration of each track, read from the file type and movie boxes held in memory, no sample read.                                                                                                                                                                                                                                      |
| Byte stream            | Port: a range of a file handed on a chunk at a time as it comes, given up at once by returning its iteration (`HttpByteStream`, `SourceByteStream`).                                                                                                                                                                                                        |
| Download               | One file of a recording downloaded while it plays, the only reader of its bytes then (`FileDownload`, ADR 0029): from where its cursors stand it plans what to ask for, give up and let go of.                                                                                                                                                              |
| Cursor                 | One reader of a track in a download: the next sample it hands out, and whether it waits for it (`SampleCursor`).                                                                                                                                                                                                                                            |
| Block                  | The bytes of one range a download asked for, allocated whole and filled from the start as they come; what counts against the budget.                                                                                                                                                                                                                        |
| Transfer               | One range a download asked for, streaming into its block until it comes whole, fails or is given up (`Transfers`).                                                                                                                                                                                                                                          |
| Download policy        | How far a download reads ahead, in seconds and bytes, how much it keeps behind the picture, how large and how many its requests are, which gaps it fetches to join ranges and when it tops up (`DownloadPolicy`).                                                                                                                                           |
| Window                 | What a download reads for: from where the picture stands (its anchor), as far ahead as the policy allows once playing, only to what the readers wait for before; a reader more than 2 s behind it wants nothing.                                                                                                                                            |
| Window anchor          | Where a download's window starts, in time and in the file, and where the key frame the picture decoded from lies: the slowest picture reader, where the picture last stood, or the sound where no picture was ever read (`WindowAnchor`).                                                                                                                   |
| Read ahead             | What a download does once playing first started: it fills the window up to the budget, paused or not, and tops it up as the picture moves on.                                                                                                                                                                                                               |
| Resume threshold       | What must lie downloaded before playback that starved plays again: the next 4 s of every lens, at most the download's budget less a request or a refill's worth; the download keeps it held once playing (`MediaBuffer`, ADR 0011).                                                                                                                         |
| Stabilization mode     | How the gyro orientation is applied: off, lock, horizon, follow.                                                                                                                                                                                                                                                                                            |
| Playback session       | The application use case that drives decoding, timing and rendering for one recording.                                                                                                                                                                                                                                                                      |
| Frame source           | A decoded video track that holds lens images: one per lens in two-track and split-file layouts, one for both lenses in a packed layout. Frame pairs hold one frame per source (`lensFrameOrder`).                                                                                                                                                           |
| Frame pair             | The decoded pictures of every lens for one instant, in lens order; owned by whoever holds it and closed exactly once.                                                                                                                                                                                                                                       |
| Frame pair queue       | Soft-capacity buffer of frame pairs between the decode pipeline and the renderer; the consumer takes the latest pair due at a time.                                                                                                                                                                                                                         |
| Decode pipeline        | Lockstep decoding of all lens tracks from a chosen time into a frame pair queue; one instance runs once.                                                                                                                                                                                                                                                    |
| Decode run             | One decode pipeline together with its own frame pair queue and whether it reached the end; the playback session holds one and replaces it whole on a seek.                                                                                                                                                                                                  |
| Start gate             | Filter at the head of a decode run: passes pairs at or after the start, keeps only the last pair before it (the frame on screen at the start).                                                                                                                                                                                                              |
| Playback clock         | Port for the media time source playback follows: wall clock in core, an audio element in the browser.                                                                                                                                                                                                                                                       |
| Frame sink             | Port that receives presentations from the playback session: the renderer, or a test double.                                                                                                                                                                                                                                                                 |
| Presentation           | One frame pair together with the media time it was shown at.                                                                                                                                                                                                                                                                                                |
| Player state           | The playback session's state machine: ready, playing, buffering, paused, seeking, ended, error, disposed; every transition is in one table. The player adds idle and loading around it.                                                                                                                                                                     |
| Recording file name    | The camera's `VID_<date>_<time>_<lens><proxy>_<sequence>.insv` convention; a hint only, verified against the file's contents.                                                                                                                                                                                                                               |
| Other lens file        | The file holding the other lens of a split-file pair (`_10_` beside `_00_`), which the camera writes beside the recording.                                                                                                                                                                                                                                  |
| Proxy                  | The low-resolution `LRV_..._01_` file the camera writes beside a recording; never played in its place (ADR 0017).                                                                                                                                                                                                                                           |
| Resource locator       | Port that tells whether a URL can be fetched, used to look for the other lens file.                                                                                                                                                                                                                                                                         |
| Decode probe           | Pre-flight decode of every lens track's first key frame under a deadline; its verdicts decide between playback and a typed error.                                                                                                                                                                                                                           |
| Error category         | Whose side a failure is on, derived from its code: `browser`, `recording`, `source`, `usage` or `internal` (ADR 0030).                                                                                                                                                                                                                                      |
| Audio segment source   | Port: the recording's audio re-packaged as fragmented MP4 (an initialization segment, then media segments from a time) for Media Source Extensions.                                                                                                                                                                                                         |
| Audio packager         | Port: a sound track's samples re-packaged, unchanged, as an audio segment source.                                                                                                                                                                                                                                                                           |
| Audio clock            | The PlaybackClock over an audio element fed through Media Source Extensions; the wall clock replaces it for silent recordings. See ADR 0007.                                                                                                                                                                                                                |
| Abort (a run)          | Ending a decode run early, discarding pending decodes and whatever arrives late. Distinct from pausing the clock and from the transport's stop (pause and rewind).                                                                                                                                                                                          |
| Body frame             | The camera's own frame: x right, y down, z forward along lens 0's optical axis. Stabilization and view rotations are expressed in it.                                                                                                                                                                                                                       |
| Lens pose              | The rotation from the body frame into one lens's frame (`lensRotation`): the calibration's yaw and pitch in the body frame, the lens's half turn, then its roll, read mirrored (ADR 0008, ADR 0025).                                                                                                                                                        |
| Canvas window          | The part of a lens's calibration canvas square that the recorded frame shows: the whole square (ADR 0014); the info record's sensor window is not applied.                                                                                                                                                                                                  |
| Feather band           | The angles from a lens's optical axis between which its blend weight fades from one to zero, centred on the overlap of the two lenses.                                                                                                                                                                                                                      |
| View state             | Where the viewer looks (yaw, pitch) and the horizontal field of view, 30 to 120 degrees.                                                                                                                                                                                                                                                                    |
| Magnification          | How far a flat picture (the panorama, the lens tiles) is enlarged from its fitted size, 1 to 8 times, and which of its points is at the centre of the viewport.                                                                                                                                                                                             |
| Framing                | Everything that frames the picture in every view mode: the view state, whose yaw also turns the panorama, and the magnification of the panorama and of the lens tiles. Each mode changes its own part and resets it alone.                                                                                                                                  |
| View context           | What a view mode needs to know about where it draws: the viewport's size and how many lenses the lens tiles show.                                                                                                                                                                                                                                           |
| Screen point           | A point of the viewport or of a picture as fractions of its width and height from the top-left corner; a zoom's focus is one.                                                                                                                                                                                                                               |
| Screen shift           | A movement across the viewport as fractions of its width and height, named apart from a drag's pixels.                                                                                                                                                                                                                                                      |
| View mode              | What the picture shows: `raw-lenses`, each lens image on its own, the mode the player opens on (ADR 0022); `equirectangular`, the whole sphere as a level, letterboxed 2:1 panorama; `normal`, a rectilinear window into the stitched sphere (ADR 0015). Every mode zooms toward the pointer (ADR 0018). Stabilization changes only the two stitched modes. |
| Picture                | What a view mode draws for a framing: a rectilinear or equirectangular picture of the stitched sphere with its rotation and area, or the lens images in tiles.                                                                                                                                                                                              |
| Raw lenses             | The view mode that shows each lens's region of its decoded frame as recorded, unstitched, in square tiles side by side or stacked; no pose, stabilization or gain. The recorded square is a little smaller than the lens's image circle, so the circles show cut at its edges (ADR 0014). The tiles zoom together and move once zoomed.                     |
| Stitching setup        | Everything the renderer needs per lens (frame slot, region, canvas window, pose, projection parameters), computed once from calibration and layout.                                                                                                                                                                                                         |
| Frame renderer         | The `PictureRenderer` that draws frame pairs on the GPU as the view mode asks: one fullscreen pass per picture, one texture per decoded frame.                                                                                                                                                                                                              |
| Picture quality        | How finely the lens images are read and how many device pixels the picture is drawn with: `fast` (one bilinear sample, one device pixel per CSS pixel), `balanced` (the mip chain along the sampling footprint, the screen's ratio up to two), `high` (four samples on a rotated grid, the ratio up to three). Kept across loads (ADR 0024).                |
| Sampling footprint     | The patch of a lens image one drawn pixel covers, from the screen derivatives of the lens coordinates; what the mip chain is read along. Taken before any gate, so it is defined along the seams and the edge of the image circle.                                                                                                                          |
| IMU frame              | How the gyro record's axes lie in the body frame; chosen from the camera model, measured per camera by the world-stillness ranking test (ADR 0009).                                                                                                                                                                                                         |
| World frame            | Gravity down along y, the body's forward at the start along z; orientations are body to world.                                                                                                                                                                                                                                                              |
| Orientation track      | The camera's body-to-world orientation per gyro sample, integrated from the gyro and pulled towards gravity.                                                                                                                                                                                                                                                |
| Stabilizer             | Strategy turning a frame's orientation into the rotation the renderer applies for a stabilization mode (off, lock, horizon, follow).                                                                                                                                                                                                                        |
| Player                 | The headless facade over one loaded recording: `load`, transport, the settings it keeps across loads (view, view mode, stabilization, gain matching, quality, sound, loop) and media-element events. The element drives it; the embed bridge drives the element.                                                                                            |
| Player status          | `idle` or `loading` (the player's own) or the session's state once loaded.                                                                                                                                                                                                                                                                                  |
| Media input            | What one file is named by: a URL read in byte ranges, or a blob (a picked `File`) sliced in place.                                                                                                                                                                                                                                                          |
| Player source          | Everything naming what to play: the main input and the optional second lens file.                                                                                                                                                                                                                                                                           |
| Source opener          | Turns a media input into the bytes the core reads, at random and as a byte stream over one resource (HTTP ranges or blob slices); the composition root's only view of where bytes come from.                                                                                                                                                                |
| Opened recording       | A recording opened as far as the pipeline needs: sample tables and codecs read, layout decided, decodability proven, timing and motion resolved, metadata assembled; owns the downloads of its files.                                                                                                                                                       |
| Pipeline               | The running parts for one opened recording: clock, renderer, stabilizing and gain-matching sinks and playback session, disposed together; the player drives it through the view, the picture settings and the session.                                                                                                                                      |
| Viewport               | The area a picture is drawn on, the player's canvas; the view modes measure it in the unit of the drags on it (CSS pixels), a renderer may give only its aspect.                                                                                                                                                                                            |
| Embed page             | `embed.html`: a full-viewport `<gyro-view>` configured by its query string, bridged to the page that embeds it.                                                                                                                                                                                                                                             |
| Embed protocol         | The versioned `postMessage` vocabulary between an embedding page and the frame: `hello`, `command`, `result`, `event`; every message validated, one trusted origin each.                                                                                                                                                                                    |
| Embed host             | The frame's side of the bridge: runs commands on the element and forwards its events.                                                                                                                                                                                                                                                                       |
| Embed handle           | The embedding page's side: the player API as promises, the events, and a state mirror.                                                                                                                                                                                                                                                                      |
| Buffering              | Playing without a picture to show: the clock waits for the decoders on starting, after a seek and when they fall behind; `waiting`/`playing` to page listeners. After a start or a seek it ends once primed; after starvation once primed and the resume threshold is downloaded.                                                                           |
| Priming                | Having enough decoded pairs queued (two, or the run over) for the clock to start without stalling at once: what a start and a seek wait for.                                                                                                                                                                                                                |
| Starvation             | Nothing due, nothing queued, the run not over and the shown frame well behind the clock: the decoders cannot keep up, so playback buffers until primed and the resume threshold is downloaded.                                                                                                                                                              |
| Preload                | Decoding the first frame while `ready`, so it shows instead of a black canvas; `preload="none"` skips it.                                                                                                                                                                                                                                                   |
| Scrub                  | A seek to the key frame at or before a time: quick to show while the seek bar is dragged; the exact seek follows when the thumb is released.                                                                                                                                                                                                                |
| Seam ring              | The circle of body directions 90 degrees from body +z, halfway between the two lenses' axes: the feather band, the seam strip and the bent join are laid out about it. Both lenses image it, so their colours there differ by exposure, not content.                                                                                                        |
| Gain match             | Per-channel gains that bring every lens's seam-ring brightness to lens 0's, measured on the GPU every half second and low-passed over 1.5 s.                                                                                                                                                                                                                |
| Seam strip             | The band of body directions 83 to 97 degrees from body +z, where both lenses see the same scene, sampled every half degree and read in 5-degree azimuth bins (0 right, 90 nadir, 180 left, 270 zenith).                                                                                                                                                     |
| Seam mismatch          | How far the lenses disagree over one bin of the seam strip for a slide of lens 0's sampling across the ring: the mean luma difference, each direction capped. Measured on the GPU by a `SeamMismatchMeter`.                                                                                                                                                 |
| Slide                  | A move of lens 0's sampling of the seam strip across the ring, in degrees away from its axis: what the mismatch meter measures the lenses' disagreement under. A bin's disparity is the slide that aligns the lenses there.                                                                                                                                 |
| Disparity              | How much farther from lens 0's axis lens 0 sees what lens 1 sees at the seam, in degrees, per azimuth bin. Parallax makes it positive for near objects (about 0.9 degrees at 2 m); for far content it is the lens model's own error at the seam, of either sign.                                                                                            |
| Lab renderer           | The renderer `pnpm measure` draws with (`@gyroview/adapter-three/lab`): the player's renderer with the instruments the measurements turn and read, a lens pose, the seam join and the mismatch meter. The player never links it.                                                                                                                            |
| Seam join              | How the stitch joins the lenses at the seam: `fixed` (the calibration's template, as the player draws it) or `bent` (each lens read across the ring by half the disparity, the two images moved up to 4 degrees between them, the rest cut), measured side by side in ADR 0026.                                                                             |
| Outbox                 | What holds the events a change announces until the change is whole, then delivers them in order; a listener's own change supersedes the older change's undelivered events (ADR 0021).                                                                                                                                                                       |
